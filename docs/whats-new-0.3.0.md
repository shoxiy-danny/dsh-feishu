# 0.3.0 升级了什么

给已经在用 0.2.0 的人。怎么升看 [升级操作](upgrade-0.3.0-agent.md)，这篇只讲变化。

公开仓：https://github.com/shoxiy-danny/dsh-feishu
这次提交：`de77276`（2026-11-06）

默认模型仍只有 `dsf`。老的 `models.json`、会话、bot 配置都不用改。

## 和 0.2.0 比

| | 0.2.0 | 0.3.0 |
|---|---|---|
| 工具进度 | 一条条蓝色进度行，工具一多就刷屏 | 一轮一张灰色折叠卡。每行一个工具，绿点完成、蓝点进行中、红点失败。跑完标题变成 `Done (3)` |
| 中途说的话 | 容易被后面的进度行盖住，或丢在卡片上面 | 正文单独发，后面的工具另开一张卡接在正文下面 |
| 失败 | 只有程序起不来才标红。命令退出码非 0 仍是绿的 | `cat` 不存在的文件、超时、被杀掉，都会标红 |
| 收尾 | 每一步空闲都可能收一次卡 | 只在这一轮真正结束时收卡 |
| 加急 | 没有 | 新工具 `buzz_user`。用户说「做完叫我」才用。长任务默认 5 分钟结束时响一次。提问卡、审批卡 2 分钟没人理响一次。都可以用环境变量关掉 |
| 语音 | 只发音频 | 可以附原文。飞书先发语音，再发一条文字 |
| `/usage` | 数字卡片 | 同一张卡上多了近 7 天柱状图和模型占比。客户端不认图时，数字还在 |
| `/resume` 的大小 | 底座升级、日志改名后，大小一栏会空 | 按文件名形状找，不再写死旧文件名 |
| 回复长短 | 没有约定 | 默认先结论，再要点。说展开才写长 |

终局回复没变：仍是绿头 `Done · 模型别名`。

## 发文件、收文件

先看自己在哪一版，再判断升不升有用。版本号：

```sh
node -p "require((process.env.DSH_HOME||require('os').homedir()+'/.dsh')+'/profiles/feishu/node_modules/dsh-feishu/package.json').version"
```

| 现在的版本 | 文件这件事 |
|---|---|
| 0.1.9 及更早 | **会好一块。** 那时候富文本里夹的文件、图片，机器人当没看见。0.2.0 起会收下，0.3.0 带着。单聊里单独发的文件，0.1.0 起就能收、能发 |
| 已经是 0.2.0 | **不会好。** 0.3.0 没改收文件，也没改发文件。还收不到就查下面，不要靠升级 |
| 不知道 | 先跑上面那条。印不出版本，多半不是从这个仓装的，先看 `package.json` 里 dsh-feishu 那一行 |

0.2.0 起能做这些，0.3.0 同样能做：

- 单聊里直接发的文件、图片、语音、视频，落到本机 inbox，路径交给模型
- 富文本消息里夹的文件和图片也会收（这一条是 0.2.0 新加的）
- 模型用 `send_file` 把本机文件发回飞书。图片按图片发，普通文件按文件发，音频加 `voice=true` 发成语音

收不到、发不出去，按这个顺序查：

1. 开放平台这个应用开了「上传图片 / 文件」。没开，机器人发文件会被飞书拒。四个应用各自开。
2. 事件订阅是长连接，勾了 `im.message.receive_v1`。停在 webhook，用户发的文件到不了进程。
3. 文件不超过 25MB。更大直接拒绝，不会发出去。
4. 回语音要本机有 `ffmpeg`。没有就发不成语音；普通文件不需要它。
5. 看当天日志里有没有 `附件失败` 或 `sendCard failed` / 上传失败。有就按那一行的原因，不要先重装。

0.3.0 只在语音上多了一点：`send_file` 可以带 `text`，飞书会在语音后面再发一条文字。普通文件的发送路径和 0.2.0 相同。
